# 私有能力网络 MVP 策略决策（A-05 / A-06 / A-07）

- 状态：**owner 已批准**（2026-07-31），数值为 MVP 起点，可随 dogfood 数据调整
- 来源 PRD：`CALL ANYTHING 下一阶段产品需求文档 v1.0`（2026-07-16 战略冻结版）
- 决策授权记录：四仓 `.trellis/tasks/07-17-call-anything-private-capability-network-mvp/decisions.md`
- 适用里程碑：A-05/A-06 → M3；A-07 → M1（元数据保留）与 M3（内容保留）
- 协议侧语义（四轴状态、合法迁移、资金矩阵）见协议仓 `docs/planned/design/mvp-architecture-decisions.zh-CN.md`。本文只定 **本平台的策略数值与执行规则**。

## 通用原则：策略快照进 Call

所有策略值在 **Call 创建时快照写入该 Call**，此后不受网络配置变更影响。原因：验收窗口与保留期都是对 Caller 的承诺，事后改配置不能追溯改变已发生交易的规则；争议发生时必须能回答"当时的规则是什么"。

## A-05 验收窗口默认值

**决策**：验收窗口按 **HotlineVersion / 档位**设定，受网络级最小/最大值约束，创建 Call 时快照。

| 层级 | 值 |
|---|---|
| 网络默认 | **72 小时** |
| 网络允许最小 | **24 小时** |
| 网络允许最大 | **7 天** |
| Quick 档 | 24 小时 |
| Standard 档 | 72 小时 |
| Deep 档 | 7 天 |

**计时规则**：

- 起点 = **Delivery Integrity 转 `verified`**（不是 Responder 提交字节的时刻）。
- 一次修订后**重新起算**完整窗口。
- 窗口内无动作 → `auto_accepted` → 结算（FR-044）。
- 争议使窗口暂停，Settlement 转 `blocked`，等 Operator 裁定（FR-045/FR-053）。

**理由**：档位越深、Caller 需要的核验时间越长，Deep 档还含人工复核产物，用统一窗口要么逼 Deep 档草率验收、要么让 Quick 档资金空转。上下界防止单条 Hotline 设出极端值（如 1 小时窗口变相强制自动接受）。

**待 dogfood 检验**：72 小时是估计值。M5 需记录实际首次接受时长分布，据此调整。

## A-06 修订经济

**决策**：固定价**含一次范围内修订，零额外费用**；沿用原 hold，不新增 hold；超范围工作必须开新 Call。

**规则**：

| 情形 | 处理 |
|---|---|
| 范围内修订（履约偏差） | 免费一次；原 hold 保持 `held`；重新交付后新窗口起算 |
| 第二次修订请求 | 拒绝——一次用尽后只剩接受或争议两条路 |
| 超范围请求 | 拒绝并提示开新 Call，**不得静默扩范围、不得自动升档** |
| 修订后仍不满意 | 走争议路径，由 Operator 判定是否履行事前契约 |

**判定基准**：修订只能修复**原 Brief 下的履约偏差**（FR-043）。"我改主意了""顺便再加一条路线"不是修订，是新 Call。Operator 在争议中只判断"是否履行事前服务契约"，不裁判开放问题的绝对真理（FR-046）。

**理由**：免费一次修订把"交付质量争议"的绝大多数情形挡在争议流程之外，成本可预测；允许多次免费修订则等于把固定价变成无限工时。禁止静默升档是为了杜绝暗中加价——PRD 明令 no silent paid upsell。

## A-07 数据保留

**决策**：**按类别分别设定保留期**，创建 Call 时快照；字节删除后留 tombstone；争议与法务保全可覆盖。

| 类别 | 默认保留期 | 说明 |
|---|---|---|
| 内容与 artifact（输入/输出/证据字节） | **30 天** | 最敏感，最短 |
| 原始执行日志 | **14 天** | 排障用途，价值衰减最快 |
| 元数据与事件（Call、状态迁移、artifact 描述符） | **180 天** | 支撑指标与对账，不含内容 |
| 审计与账本 | **365 天** | 资金与内容访问记录，最长 |

**规则**：

- 删除字节后保留 **tombstone**（描述符 + checksum + 删除时间与原因），使历史 Call 仍可解释，且删除动作本身可审计（FR-063 精神）。
- **争议或法务保全期间暂停删除**，裁定后恢复计时。
- 保留期为**网络可配置**，但 Call 快照的值优先——事后调短配置不追溯删除已承诺保留的数据。
- **内容默认不用于训练**（PRD 11.5），删除、导出与 Operator 内容访问三者均可追踪。

**理由**：单一保留期会在"敏感内容留太久"与"元数据删太早导致无法对账"之间二选一。分类保留让内容尽早消失、账目足够长久。当前平台侧无任何保留/删除机制，是需要从零建的能力。

## 与现状的差距（供 M1/M3 拆解）

| 现状 | 差距 |
|---|---|
| 结算跟随执行完成，无验收门 | 需 A-05 验收窗口、自动接受定时器、争议冻结 |
| 无修订概念 | 需 A-06 一次修订轮次、范围校验、窗口重启 |
| 无任何保留/删除机制；请求快照永不淘汰 | 需 A-07 分类保留、tombstone、保全覆盖；与请求存储重构同批做 |
| 无备份/恢复工具链 | 保留策略需要可验证的删除路径，先补备份再谈删除 |
