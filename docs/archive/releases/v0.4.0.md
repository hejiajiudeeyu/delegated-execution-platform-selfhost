# Release `v0.4.0`

## Release

- version: `v0.4.0`
- date: `2026-08-02`

## ⚠️ Exposure change — read before upgrading

**The relay's business routes go back onto the public edge.** `v0.3.0` shipped
the authentication that makes this safe (admin token, receiver-scoped tokens,
visibility leases, lease-guarded ack), but the edge stayed closed from the
2026-07-31 bleeding-stop, so the fix has been sitting behind a `403`.

Reopening is what makes a Provider device off the platform's own host possible
at all: the responder long-polls the relay inbox, and an edge that refuses it
means the device can never receive work.

Before rolling, confirm two things about your deployment:

1. `RELAY_ADMIN_TOKEN` and `RELAY_TOKEN_SECRET` are real generated values, not
   the `change-me` placeholders. On a public relay the admin token is
   read/inject/delete over every task envelope. The workspace security review
   now treats both as secret-hygiene blockers.
2. `RELAY_ALLOW_UNAUTHENTICATED` is **not** set. It was a trusted-network
   escape hatch; on a public edge it is a full compromise.

If either is wrong, keep the edge closed until it is fixed.

## Summary

- **restart reconciliation** (`POST /v1/requests/:id/reconcile`): a responder
  process that died mid-execution used to leave its call in `held` forever,
  with no path to a terminal event or a refund. A signed report from the
  device now closes the call out. The endpoint cannot settle: a report
  claiming `delivered` is refused with `409
  RECONCILIATION_CANNOT_CLAIM_DELIVERY`, and the billing call is hardcoded to
  the failed path, so unknown work resolves in the caller's favour or not at
  all. Reports are Ed25519-verified against the responder's registered keys,
  including rotated-away ones, since a device that crashed during a rotation
  still holds the old key. Idempotent per `attempt_id`, with the billing
  store's own `held` check as the structural backstop.
- **console aggregate reads**: `GET /v1/admin/attention` (hotlines and
  responders awaiting review, calls past the grace window with no terminal
  event, funds still held after a call ended, unavailable devices, with
  `nothing_to_do` explicit) and `GET /v1/admin/requests/:id` (timeline,
  artifacts, billing, responder capacity and version, hotline and audit events
  joined server-side). Both refuse to report a state the platform does not
  track: untracked axes report `tracked:false` with a reason rather than a
  plausible value.
- **relay back on the public edge**, as described above.
- integration suites no longer run from a hand-maintained file list, which had
  silently excluded new suites from `npm test`; the directory glob the vitest
  config already declares is now the only source. Integration coverage went
  from 86 to 96 passing without any new behavior.

## Compatibility

Roll all three images together. No environment variables are added or removed
relative to `v0.3.0`; the exposure change is at your edge (nginx or Caddy), not
in the images.
