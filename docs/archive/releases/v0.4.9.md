# Release `v0.4.9`

## Release

- version: `v0.4.9`
- date: `2026-08-07`

## Summary

The operator can end things. Until now they could not, and that quietly broke
the alerting shipped in v0.4.5.

Both live kinds of attention item were unclearable for a device that no longer
exists. A call leaves `call_stuck` only by reaching a terminal execution state,
and the only things that produced one were the device itself and a signed
reconciliation report — neither is coming from a machine that is gone.
`device_unavailable` counts any responder still holding a hotline, and
disabling the hotline does not change what the responder holds.

This deployment had 12 attention items, 11 of them from June and July
rehearsals. FR-066 alerting reuses that same computation, so switching alerting
on would have paged every six hours, forever, about calls nobody could close.
v0.4.5 promised that silence after an alert means resolved; an item no action
can resolve breaks that promise for every other item too.

- **`POST /v1/admin/requests/:id/close`** ends an abandoned call. A reason is
  required — a judgement with no stated reason is an unauditable operator
  action. It **never settles**: like the reconciliation endpoint, it can only
  refund, because an operator ending an abandoned call is not evidence that
  anything was delivered. Held funds are refunded; an existing settlement is
  left alone and reported as such rather than quietly reversed.

- **`POST /v2/admin/responders/:id/retire`** withdraws a gone device's claim to
  be serving anything: its hotlines are disabled, its hotline list is cleared,
  and it stops counting as unavailable. The record is kept — retiring withdraws
  a claim, it does not erase history.

## Compatibility

Drop-in and additive. `CANCELED` joins the execution event projection, so a
closed call reads as `canceled` on the execution axis.
