# Release `v0.4.4`

## Release

- version: `v0.4.4`
- date: `2026-08-05`

## Summary

A long call is no longer a black box between ACKED and COMPLETED (FR-036).

- **the platform accepts progress observations.** `POST
  /v1/requests/:id/events` now takes the observational pair the contracts
  froze — `PROGRESS` (stage `input_fetching`/`executing`/`output_uploading`,
  optional percent and message, per-attempt monotonic `seq`) and
  `SOFT_TIMEOUT` — alongside the terminal `COMPLETED`/`FAILED`. Observations
  never touch billing, never move the execution projection, are refused with
  409 once execution is terminal, and `PROGRESS` rows are pruned against
  their own budget (`PLATFORM_REQUEST_PROGRESS_HISTORY_LIMIT`, default 50) so
  telemetry can never evict the lifecycle events the projection reads.

- **the console timeline shows them.** `/calls/:id` renders progress rows
  hollow and grey — stage in plain words, percent, the device's message —
  so lifecycle events stay the skeleton of the timeline.

- **a progressing call is no longer flagged stuck.** Progress freshens the
  call's last-event timestamp, so the attention feed's stuck guardrail can
  finally tell "legitimately grinding through page 40" from "silent for an
  hour". A silent call still trips it.

- **closes a silent defect:** the responder has posted `SOFT_TIMEOUT` since
  the hook was written and the platform 400-rejected every one of them, with
  both sides swallowing the error. The client sent observations nobody could
  see; now they land.

- **console robustness:** an error body (expired session, 404) was rendered
  as if it were a call and crashed `/calls/:id` to a white page; it now shows
  the error panel it always should have.

Requires `@delexec/contracts@0.1.5` (published) and `@delexec/ops` ≥ 0.1.8 on
devices for the beats to be emitted; older clients keep working, they just
stay silent.

## Compatibility

Drop-in over `v0.4.3`. One new optional env
(`PLATFORM_REQUEST_PROGRESS_HISTORY_LIMIT`), two new error codes
(`CONTRACT_INVALID_PROGRESS`, `CONTRACT_EXECUTION_TERMINAL`), no changes to
existing endpoints' accepted payloads.
