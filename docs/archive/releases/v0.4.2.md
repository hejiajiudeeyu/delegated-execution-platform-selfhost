# Release `v0.4.2`

## Release

- version: `v0.4.2`
- date: `2026-08-02`

## Summary

The operator console's third rebuild, UI half. Backend aggregates shipped in
`v0.4.0`; this is what consumes them.

- **the home page answers "what needs me now"**. It replaces a panel of three
  health lights and a setup-only "next step" card that went silent once
  initialization was done. Rows are real work — pending reviews, calls past the
  grace window, funds still held after a call ended, unavailable devices — and
  each leads to where that work is done. With nothing pending it says so
  plainly, and it names the situations it cannot yet see (disputes, acceptance
  expiry) so that silence about an unbuilt feature is not mistaken for silence
  about a healthy system.
- **`/calls/:id` exists**. Previously there was no detail route anywhere in the
  console. The page joins timeline, artifacts, billing, device and hotline into
  one story, draws the four state axes as four independent rows, and marks an
  axis the platform does not track as untracked with the reason.
- **a terminology layer**: internal field names get one plain-language sentence,
  defined once.
- **fix: the console dev server could never reach a gateway.** In DEV the API
  base was a bare `/`, `new URL()` rejects a relative base, and the resulting
  throw was classified as "gateway unreachable" — so local development showed a
  dead console no matter what was running. Both earlier console rebuilds were
  built against this.
- **fix: the four-axis reasons were English** inside an otherwise Chinese
  console. Corrected at the API rather than translated in the client.

## Compatibility

Drop-in over `v0.4.1`. No environment or API changes. The console is served by
the gateway image, so roll `rsp-gateway` at minimum; rolling all three together
remains the supported path.

## Operator note

The console needs its own admin credential configured (会话与解锁 → 网关凭据)
before any of these pages can load data. A console that is unlocked but has no
verified admin key will show the credential prompt rather than the feed.
