# Release `v0.4.5`

## Release

- version: `v0.4.5`
- date: `2026-08-06`

## Summary

The platform can now tell you something is wrong (FR-066). Before this it had
no outbound capability at all — no SMTP, no webhook, no dependency of any kind
— so every problem it detected waited for someone to open the console.

- **alerts go to a webhook you configure.** `Settings -> Alerts` in the
  console (no SSH). The platform POSTs one JSON object per alert; set a
  signing secret and each POST carries `x-delexec-signature: sha256=<hmac>`
  over the raw body. Works with a Feishu/WeCom bot, Bark, ntfy, or your own
  script.

- **one definition of "wrong".** Alerts are derived from the same attention
  computation the console home page renders, extracted so both read it. They
  are not a second opinion that can drift from what you see on screen.

- **open, repeat, close.** An alert fires when the problem appears, again
  every `renotify_hours` (default 6) while it is still open, and once more
  when it clears — so silence after an alert always means resolved, never
  forgotten. Tracking is per device/call, so one recovery cannot silence
  another problem, and it survives a restart without re-announcing everything.

- **failed deliveries are visible.** A webhook that silently fails would
  reproduce exactly the silence this feature exists to end, so every attempt
  is recorded and shown on the alerts page.

- **liveness ping (dead man's switch).** platform-api cannot report
  platform-api being down — which is the shape of the 2026-07-04 outage that
  ran 5.5 hours before anyone noticed. Point `liveness_url` at an external
  heartbeat monitor (Healthchecks.io, Uptime Kuma push, BetterStack) and the
  platform GETs it on a schedule; the monitor alarms when the pings stop.
  **This is the only part of the setup that covers a platform outage.** The
  console and `/v1/admin/alerts/status` both say so rather than letting
  outage silence read as good news.

- **offline detection meets NFR-R05.** `OFFLINE_THRESHOLD_S` 180s → 120s
  (four missed 30s heartbeats); 180s could not detect an offline device
  within two minutes no matter how fast anything downstream reacted.

## Compatibility

Drop-in over `v0.4.4`. New admin endpoints (`/v1/admin/alerts/config`,
`/status`, `/test`), one new error code (`CONTRACT_INVALID_ALERT_CONFIG`), no
changes to existing endpoints. Alerting is off until a webhook URL is saved.

Devices are declared offline after 120s of silence instead of 180s; a device
on a heartbeat interval longer than 30s should have its interval reviewed.
