# Release `v0.4.7`

## Release

- version: `v0.4.7`
- date: `2026-08-06`

## Summary

A hotline must be a contract before it can be published (FR-010, FR-013,
M2 unit 2).

An audit of this deployment on 2026-08-06 found what this prevents: the four
demo hotlines carried schemas and valid examples, while the **only hotline that
had ever done real work declared no input schema, no output schema, no examples
and no limits**. It was callable because nothing ever required otherwise, so its
contract existed only in whoever wrote the adapter's head.

- **approval now checks the declaration.** Both schemas, at least one worked
  example each way, a statement of what the hotline is *not* for, and examples
  that actually satisfy the schemas they illustrate. Refusal returns
  `CONTRACT_HOTLINE_INCOMPLETE` with an itemised `problems` list, which the
  console renders as a list rather than a paragraph.

- **checked at approval, not at submission.** A device must still be able to
  enroll — an enrollment that fails on a documentation problem looks like a
  broken device — and the operator gets one list of everything missing instead
  of a Provider decoding a rejection from a log.

- **an example that its own schema rejects is worse than no example.** Someone
  copies it, the call fails, and the contract still looks fine. Examples are now
  validated against the schema they claim to illustrate, and the failing example
  is named.

- **examples have one shape.** Real submissions used `{title, input}` /
  `{title, output}`; the seeded demo catalogue used `{title, description,
  params}` / `{..., result}`. Two shapes is why nobody could validate them. The
  demos move to the shape real data already uses; the marketplace page reads the
  new keys and falls back to the old ones for existing data.

- **the bootstrap hotlines carry their examples in the catalogue**, not only in
  the template bundle. They previously would have failed their own publication
  rule.

## Compatibility

**Behaviour change at approval.** Already-approved hotlines are not
re-validated and nothing is disabled by this release. But the next time an
incomplete hotline is approved, approval refuses until its declaration is
complete. On this deployment that means `local.mineru.pdf.parse.v1`: it keeps
running, and it cannot be re-approved until it declares schemas, examples and
limits.

Requires `@delexec/contracts@0.1.8` (adds `ajv` as a runtime dependency).

## Why this comes before M3

M3 adjudicates whether a delivery met its contract and allows one in-scope
revision. Both are unanswerable when the contract does not say what goes in,
what comes out, or what the hotline was never meant to do.
