# Release `v0.4.6`

## Release

- version: `v0.4.6`
- date: `2026-08-06`

## Summary

A Call now pins the contract it was made under (FR-014, M2 unit 1).

Before this, the catalog held one mutable record per hotline and a resubmission
overwrote it in place, while a Call recorded only `hotline_id`. A Provider could
change the schemas, limitations and pricing of a contract while a call made
under the old ones was still running, and afterwards nothing could say which
contract the call had actually agreed to. `submission_version` did not help: it
counts submissions and labels a record that is about to be overwritten.

- **approval is publication.** When a hotline is approved it becomes callable,
  so that is when its contract fields are frozen into a version carrying a
  `sha256` digest of its content. Publishing is idempotent by content:
  re-approving unchanged content keeps the existing version rather than minting
  a number that only records a second click.

- **a Call binds its version before anything is charged or dispatched**, and
  keeps it. Re-issuing a task token is not a new agreement. The binding travels
  in the signed task token (`claims.hotline_version`) and in
  `delivery_meta.hotline_version`, so the responder is told which contract it is
  executing and the binding cannot be edited in transit.

- **reads for a bound call go to the pinned version, never the catalog.**
  `/calls/:id` shows which contract version the call agreed to and says plainly
  when the hotline has moved on since. A call with no pin reports that it
  predates versioning rather than borrowing today's contract.

- **integrity is reported, not assumed.** `GET /v2/admin/hotlines/:id/versions`
  lists the history and marks any stored version that no longer hashes to its
  own digest as `digest_mismatch`. Nothing in the product edits a published
  version; if a bad migration or a hand-edited snapshot ever did, this is the
  only way it becomes visible.

- **legacy hotlines converge.** A hotline approved before versions existed gets
  one on its first binding rather than staying unpinned forever.

## Compatibility

Drop-in. Additive on the wire: `claims.hotline_version` and
`delivery_meta.hotline_version` are new fields, and no client rejects unknown
fields. Calls created before this release show "predates versioned hotline
contracts" instead of a version.

Requires `@delexec/contracts@0.1.7` (canonical JSON, contract digest, frozen
version document and its validators).

## Why this comes before M3

M3 has to decide whether a delivery met its contract, allow one in-scope
revision, and adjudicate disputes. All three are unanswerable while "which
contract" has no answer.
