# Release `v0.4.8`

## Release

- version: `v0.4.8`
- date: `2026-08-06`

## Summary

The platform stops inventing a contract for a hotline that declared none.

The marketplace views fell back to the template bundle when a catalogue record
carried no schema, and the bundle's built-in default is a generic
`{text, instruction}` → `{summary}` shape. A hotline that declared nothing was
therefore advertised as a text summarizer.

On 2026-08-06 that is exactly what this deployment was doing with a PDF parser:
`/marketplace/hotlines/local.mineru.pdf.parse.v1` returned a complete-looking
contract in which every field was wrong. A caller reading the catalogue would
have sent `text` to something that parses documents through the artifact
channel.

- **`input_schema`, `output_schema` and the attachment declarations now come
  only from the hotline's own record.** No template fallback.
- **`contract_declared` says which case you are looking at**, so a missing
  contract reads as missing rather than as a contract nobody can satisfy.

This follows the rule the attention feed and the v0.4.7 publication gate already
set: an unbuilt or undeclared thing has to say so. An invented answer is worse
than silence, because someone will act on it.

## Compatibility

Drop-in. `/v2/hotlines/:id` and `/marketplace/hotlines/:id` stop returning a
fabricated schema for hotlines that never declared one; they return `null` and
`contract_declared: false`. Hotlines that declared their own schemas are
unaffected.

Pairs with `@delexec/ops@0.1.9`, where a worker declares its own contract
(`--contract`) and device registration carries it — so the hotlines that were
relying on the fabricated default can state a real contract instead.
