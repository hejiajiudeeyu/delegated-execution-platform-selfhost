# Release `v0.3.0`

## Release

- version: `v0.3.0`
- date: `2026-08-01`

## ⚠️ Breaking changes — read before upgrading

This release changes two public behaviors and adds two required environment
variables. A deployment that upgrades without acting on these will not work.

1. **The relay now requires credentials and refuses to start without them.**
   Set `RELAY_ADMIN_TOKEN` and `RELAY_TOKEN_SECRET` before rolling, or the
   relay container exits at boot. `RELAY_ALLOW_UNAUTHENTICATED=1` is an
   explicit escape hatch for a trusted network; it is not a default.
   `platform-api` also needs `RELAY_ADMIN_TOKEN` to reach the relay.
2. **Anonymous responder enrollment is gone.** `POST /v2/responders/register`
   now requires an authenticated caller or responder. Any integration that
   enrolled a device without a credential will receive `401`.

Both are deliberate. The relay carried task envelopes with no authentication
at all, and anonymous enrollment let anything that could reach the API join
the trust domain by asserting a display name.

## Summary

- **relay authentication and visibility leases**: two bearer credentials guard
  the six business routes — a deployment-held admin token, and HMAC-signed
  receiver tokens scoped to exactly one inbox, minted by an admin-only
  endpoint. Health and build probes stay public. Polling now claims messages
  under a visibility lease instead of handing the same envelope to every
  poller; an ack may carry its lease id and a superseded lease is refused with
  `409`, so a consumer whose lease expired cannot delete work another consumer
  has since claimed. Repeat acks stay idempotent. Memory and sqlite stores
  share the semantics, and sqlite lease columns are added in place so an
  existing relay volume keeps its queued messages.
- **controlled device enrollment**: enrollment requires a credential and binds
  the device to the enrolling identity.
- **device version and capacity reporting**: heartbeats carry
  `version` (agent/runtime/build) and `capacity`
  (`max_concurrent`/`in_flight`/`accepting`), surfaced in the operator
  responder view. Unreported capacity stays `null` rather than `0` — "not
  reported" and "no capacity left" must not look alike — and a partial
  heartbeat no longer clears previously reported facts. A device may declare
  `maintenance`, which is sticky: a fresh heartbeat does not silently promote
  it back into routing. Conversely a stale heartbeat outranks a stale
  self-report, so a device claiming healthy while silent reads as `offline`.
- **artifact channel**: allocate a scoped slot, upload bytes, commit a claimed
  checksum, download under a scoped grant. A checksum mismatch is refused and
  leaves the artifact `allocated`, so failed bytes never become a delivered
  artifact. Grants are per artifact and per direction; committed bytes are
  immutable; an uncommitted artifact never serves bytes. Descriptors carry no
  bucket, object key, presigned URL or local path.
- **observed build facts**: every service serves `GET /buildz` reporting
  component, version, git SHA, image digest, release id, manifest hash, and —
  for the gateway — the console asset hash it actually serves. Unset facts
  report `null` rather than a guess, so a workspace drift check can tell "not
  injected" from "wrong".
- restored the two integration test files that had been silently dropped from
  the suite, and repaired them against the current API surface.

## New environment variables

| Variable | Service | Required | Notes |
| --- | --- | --- | --- |
| `RELAY_ADMIN_TOKEN` | relay, platform-api | **yes** | shared operator credential |
| `RELAY_TOKEN_SECRET` | relay | **yes** | signs receiver-scoped tokens; rotating it revokes every issued token |
| `RELAY_VISIBILITY_TIMEOUT_S` | relay | no | lease window, default `60` |
| `ARTIFACT_STORE_PATH` | platform-api | recommended | artifact bytes; without it bytes are in memory and lost on restart |
| `ARTIFACT_MAX_BYTES` | platform-api | no | upload limit, default 64 MiB |

`deploy/public-stack` adds a `public-stack-artifact-data` volume.

## Upgrade checklist

1. Add `RELAY_ADMIN_TOKEN` and `RELAY_TOKEN_SECRET` to the deployment `.env`
   (strong values; do not reuse the examples).
2. Add `ARTIFACT_STORE_PATH` and the artifact volume, or accept that artifact
   bytes are memory-only.
3. Roll the images, then verify: `/healthz`, `/platform/healthz`, `/console/`
   return 200; `/platform/buildz` reports the expected release; relay business
   routes are not reachable from the public edge.
4. Any client that enrolled devices anonymously must supply a credential.
